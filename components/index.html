Components

Twenty-nine components, sixteen of them at the tier that means each was the subject of its own ticket. Every one is a plain function: it takes a draw context and a rectangle, writes every cell of that rectangle exactly once, and returns what happened. There is no widget object to construct, nothing to register, and nothing that exists between frames.

This page is generated from the freeze — the same value the crate’s own obligations are queries over — so a component cannot be added to the library and left off the page, and a renamed entry point fails the build rather than the link.

Each row’s sentence is that component’s own documentation, and the spellings are what you call: name takes the common case, name_with takes an options struct, name_into writes into a rectangle you already hold.

The pictures under each table are frames, not photographs. Every one is composited by this engine with no terminal in the loop and written as SVG instead of as terminal bytes — the same composited picture your own terminal would be sent, in the same frame that would have sent it. They are regenerated by one command and compared on every build, so a component whose drawing changes without its picture changing is a failed pipeline rather than a stale image.

What is not here

Section titled “What is not here”

media. The mechanisms are built and the freeze ships none of them as a component: a picture as half-blocks, a QR code, a waveform. The family exists in the catalogue and has no v1 row.

API documentation. It belongs on docs.rs and is not mirrored here. Until 0.1.0 is published the links above go to the source, which is the honest destination rather than a docs.rs URL that 404s.
