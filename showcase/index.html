What it looks like

Twenty-one applications, one file each. They are the component surface’s only consumer, and repeatedly the thing that found the defect the test suite could not: a gate exercises a component where its author put it, and an application puts it somewhere else.

The last three are ports of programs people use. A port’s shape is not ours to argue with — so what it cannot express is a fact about this surface rather than a matter of taste, and three ports asking for the same missing option is what turns a taste into a gap. All three run on invented data: a real readdir or a real kubectl puts the interesting failures in the transport instead of in the library under test.

The three ports

Section titled “The three ports”

What these recordings are

These three are recordings of a real terminal, which is the honest instrument for something that moves. Everything below is the opposite and so are the pictures on the Components page: frames this engine composited with no terminal in the loop, written as SVG rather than as terminal bytes — the frame itself rather than a photograph of one.

Every screen

Section titled “Every screen”

One picture per application, each a single composited frame. caps is the one with none: it attaches, asks the terminal what it can do, detaches and prints, so there is no frame to be a picture of.

capsWhat this terminal answered, and nothing else. It draws no frame: attach, read Capabilities::report, detach, print — so nothing it prints can be a consequence of anything a component did. Three terminals are in the quirk table for exactly that, recognised by their environment because it is not a thing a terminal will admit to; VITUI_FORCE_LEGACY_SGR=1 settles it in one run—

Nine pods, four deployments, four services, three nodes and five namespaces, all hashed out of their own names. It is a stack of views and Esc is pop, which is what makes logs, YAML and a description levels rather than modals — they scroll with the keys the table has and leave the way it does. What writing them found

Section titled “What writing them found”

Four defects on this list were found by an application and by nothing else, and each is a class rather than a slip.

  • Two panels drawn from one source line are one widget. An id comes from the call site, so a loop over two panels hands the second the first one’s focus, cursor and hover — the screen looks perfect and the wrong panel answers the keyboard. A gate never meets it, because a gate draws one subject.
  • A key release is an event too. A modern terminal reports both edges of a keystroke, so an application matching on the key code alone scrolled two lines per press — and read perfectly on a legacy terminal.
  • A dialog that closes does not give the keyboard back to whoever opened it. The focused widget stopped drawing, so the focus moved to the nearest survivor in the previous frame’s order, which for a two-panel screen is the other panel.
  • A match on the character is half a keyboard. A terminal speaking the enhanced protocol sends the base key and the shift bit, so ? arrives as / with SHIFT. Two applications opened the wrong thing on ? until they were bound through a key map.

All four are fixed, and all four are why the applications are a workspace member that CI builds rather than a folder of snippets.
